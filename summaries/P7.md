# P7. PowerCenter → Cloud 현대화
> 온프레미스 PowerCenter 도메인을 IDMC에 등록해 CDI-PC로 운영하고, 기존 자산을 평가·변환해 Cloud Data Integration으로 옮기는 단계다.

## 이 단계에서 배우는 것
- CDI-PC 구조: 데이터와 세션·워크플로 실행은 온프레미스 도메인에 두고 관리는 IDMC에서 한다
- CDI-PC 도메인을 IDMC에 등록·수정·해제·삭제하는 절차
- Repository Assessment → Asset Conversion → Bulk Metadata Update로 이어지는 현대화 흐름
- CDI-PC Designer와 Workflow Manager로 mapping, session, workflow를 다루는 방법
- 10.5.1 기준 제품별 업그레이드 경로

## 핵심 개념
| 개념 | 설명 |
|---|---|
| CDI-PC | Cloud Data Integration for PowerCenter. IDMC의 domain management service와 연결된 온프레미스 도메인을 만든다. 기존 Informatica domain을 CDI-PC로 마이그레이션할 수도 있다. |
| Domain registration | 온프레미스 도메인과 IDMC 사이 통신을 여는 작업. 등록해야 CDI-PC에서 job을 만들고 돌리고 모니터링할 수 있다. |
| Secure Agent group | 도메인 등록 시 지정한다. 그룹 안의 Secure Agent가 도메인에 접근할 수 있어야 한다. |
| Repository Assessment | PowerCenter나 Model repository를 백업해 IDMC에 복원한 뒤 변환 가능성을 평가한다. 결과는 Automated, Partial 같은 범주로 나뉜다. |
| Asset Conversion | mapping, mapplet, session, workflow를 각각 CDI의 mapping, mapplet, mapping task, taskflow로 바꾼다. |
| Repoint Configuration / Connection Map | 앞의 것은 assessment에서 다른 endpoint로 repoint할 수 있는지 평가하고, 뒤의 것은 conversion에서 PowerCenter connection을 IDMC connection에 대응시킨다. |
| Bulk Metadata Update | 변환된 mapping·taskflow의 필드, advanced property, connection 정보를 한 번에 고친다. assessment ZIP에 든 BulkUpdateConnectionTemplate.xlsx를 쓴다. |
| My Jobs | assessment, conversion, parameter file conversion, bulk update job을 추적하고 리포트·로그를 내려받는 페이지. |
| Mapplet | 여러 mapping에서 재사용하는 transformation 묶음. mapplet을 고치면 모든 인스턴스에 반영된다. |
| Session Configuration Object | commit·load, 로그, 오류 처리 설정을 담는다. 폴더마다 기본 객체가 있고, 수정하면 이를 쓰는 세션이 모두 따라 바뀐다. |

## 실습 흐름 (LAB)
1. 조직·라이선스 정보와 CDI-PC 서비스 역할·권한을 확인한다. [Getting Started With Cloud Data Integration For PowerCenter]
2. IDMC에 로그인해 CDI-PC Home page로 들어가고 설치 파일을 내려받는다. [Getting Started With Cloud Data Integration For PowerCenter]
3. Home page의 Register a Domain에서 Add New Domain을 누르고 Domain Name, Domain Display Name, Gateway Host, Gateway Node Port(HTTPS)를 입력한다. [Domain Registration]
4. Secure Agent group과 인증 방식(Kerberos 또는 non-Kerberos)을 지정하고 Validate를 거쳐 Register를 누른다. [Domain Registration]
5. Explore page와 Domain Details page에서 도메인 상태를 보고, Alerts and notifications, Asset logs, Metering information을 확인한다. [Getting Started With Cloud Data Integration For PowerCenter], [Domain Registration]
6. Repoint configuration을 만들고 assessment task를 돌려 결과 파일을 받는다. [PowerCenter Modernization]
7. Connection map과 conversion properties 구성을 만든 뒤 conversion task를 실행하고, My Jobs에서 결과를 검증하고 bulk update task로 마무리한다. [PowerCenter Modernization]

## 현업 팁 · 주의점
- 등록이 Registering 상태에서 멈추면 최소 15분 기다린 뒤 Refresh를 누른다. Offline으로 보이면 reconcile을 진행한다.
- Kerberos 도메인은 Administrator tool과 도메인의 TLS 인증서를 브라우저에 먼저 넣어야 한다. OS 사용자와 도메인 관리자 계정이 같아야 한다.
- non-Kerberos로 등록한 도메인을 Kerberos로 바꾸면 수정으로는 안 되고 다시 등록해야 한다. 도메인 수정은 August 2023 이후 버전에서만 된다.
- 도메인을 deregister하면 실행 중인 job이 멈출 수 있다. 다른 조직이나 pod로 옮기려면 먼저 deregister한다.
- Conversion 전에 assessment를 끝내고 필요한 asset 권한을 부여한다. Partial로 분류된 자산은 변환 후 수동 손질이 필요할 수 있다.
