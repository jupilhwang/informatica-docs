# P5. PowerCenter (On-Prem) 핵심
> Informatica domain과 PowerCenter 리포지토리를 세우고, Designer로 매핑을 만들어 Workflow Manager·Workflow Monitor로 세션을 실행·감시하며, 튜닝·배포·보안까지 온프렘 ETL 운영 전반을 다루는 단계다.

## 이 단계에서 배우는 것
- domain, node(gateway·worker·master gateway), Service Manager, Repository Service, Integration Service의 구조와 역할
- 서비스 설치 후 domain 구성, application service 생성, 클라이언트 설치까지의 설치 순서
- Designer의 Source Analyzer·Mapping Designer로 source/target 정의와 매핑을 만들고, Transformation Language로 식을 쓰는 방법
- Workflow Manager로 Session·Workflow를 만들고 partitioning, pushdown optimization, recovery, parameter file로 운영하는 방법
- Repository Manager의 versioning, label, deployment group으로 팀 개발·배포를 하고 pmcmd·infacmd로 명령행 운영을 하는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Informatica domain | PowerCenter 관리의 기본 단위. 하나 이상의 node와 domain configuration repository(관계형 DB)로 이뤄진다. |
| Node | 서버에 설치한 Informatica의 논리적 표현. gateway node는 domain DB를 갱신할 수 있고 worker node는 application service만 돌린다. master gateway node는 한 번에 하나다. |
| Service Manager | 모든 node에서 처음 뜨는 Java 프로세스. master gateway node에서는 Log, User Management, Licensing 같은 Master Core Services를 함께 돌린다. |
| PowerCenter Repository Service | 소스·타깃·매핑·세션 같은 메타데이터를 담은 PowerCenter repository를 관리한다. repository에는 실제 데이터가 아니라 정의만 저장된다. |
| PowerCenter Integration Service | workflow를 실행해 source에서 데이터를 읽고 변환한 뒤 target에 쓴다. Load Balancer가 Session·Command 등 task를 node에 분배한다. |
| Mapping / Mapplet | source → transformation → target 데이터 흐름. 모든 매핑에는 Source Qualifier가 들어간다. mapplet은 transformation 묶음을 재사용하는 객체다. |
| Transformation | 데이터를 생성·변경하는 매핑 구성 요소. Filter처럼 행 수를 바꾸는 active, HTTP처럼 바꾸지 않는 passive로 나뉜다. |
| Session / Workflow | session은 Integration Service가 언제·어떻게 source에서 target으로 데이터를 옮길지 정한 task다. workflow는 session, email 알림 같은 task를 어떻게 실행할지 정한 지시 묶음이다. |
| Parameter file | 세션 실행마다 바뀌는 값(DB connection, source/target 파일, mapping parameter)을 외부에서 넘기는 파일 |
| Deployment group | 팀 개발에서 배포할 객체를 묶는 global object. Repository Manager의 Copy Wizard로 다른 repository에 복사한다. |

## 실습 흐름 (LAB)
각 lesson은 이전 lesson 결과를 이어서 쓰므로 lesson 하나는 한 번에 끝낸다.
1. Administrator tool에서 user와 group을 만들고 group에 privilege를 준다. repository에 tutorial folder를 만들고 예제 source table을 생성한다. [Getting Started · Lesson 1]
2. Designer > Tools > Source Analyzer에서 Sources > Import from Database로 ODBC data source를 골라 source definition을 가져온다. target definition을 만들고 SQL을 생성·실행해 target table을 만든다. [Getting Started · Lesson 2]
3. Mapping Designer에서 모든 source 행을 target에 넣는 pass-through mapping을 만든다. Workflow Manager에서 Session과 Workflow를 만들고 실행한 뒤 Workflow Monitor로 확인한다. [Getting Started · Lesson 3]
4. Expression, Aggregator, Lookup을 넣어 집계 값을 계산하는 매핑을 만들고 session·workflow로 실행한다. [Getting Started · Lesson 4]
5. Stored Procedure, Filter, Sequence Generator로 fact table과 dimension table을 채우는 매핑을 만든다. [Getting Started · Lesson 5]
6. XML schema를 source로 쓰고, 급여 3종을 BASESALARY·COMMISSION·BONUS 컬럼으로 pivot한 뒤 Expression으로 합계를 내고 Router로 부서별 XML target에 나눠 쓴다. [Getting Started · Lesson 6]
7. (확장) session 속성 Properties 탭에서 pushdown을 Full로 바꾸고 Mapping 탭의 View Pushdown Optimization으로 생성 SQL과 pushdown group을 확인한다. [How to use full pushdown optimization in powercenter]

## 현업 팁 · 주의점
- nodemeta.xml이나 domains.infa를 손으로 고치면 node 간 연결이 바뀔 수 있다. 변경은 infasetup updategatewaynode / updateworkernode로 한다. [Informatica architecture nodes and domains]
- gateway node가 여럿이면 master gateway가 죽어도 다른 gateway node 중 하나가 새 master로 선출된다. worker node는 master가 될 수 없으므로 HA를 원하면 gateway node를 2개 이상 둔다. [Informatica architecture nodes and domains]
- full pushdown에서는 DB가 오류를 처리하므로 reject file이 남지 않고, 오류가 나면 트랜잭션 전체가 rollback된다. 대소문자, 숫자·날짜의 Char 변환, sort 시 null 순서, precision 차이로 Integration Service 실행 결과와 다를 수 있다. [How to use full pushdown optimization in powercenter]
- PowerCenter repository는 checkout을 passive 방식으로 보호한다. 다른 사용자는 check in 시점에야 충돌을 안다. undo checkout을 하면 변경분이 사라지고, 이전 버전은 보기·비교만 되고 복원은 안 된다. [Team based development in the powercenter repository and th]
- 설치 시 기본 administrator 계정이 만들어진다. 설치 후 처음 로그인하면 이 계정의 비밀번호부터 바꾼다. [Security Guide]
