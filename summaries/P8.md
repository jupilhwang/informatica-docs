# P8. Data Quality & Profiling
> 프로파일링으로 데이터 상태를 진단하고, Rule Specification·Dictionary·Exception 관리로 품질 문제를 찾아 고치는 단계다.

## 이 단계에서 배우는 것
- IDMC Data Profiling에서 runtime environment, connection, project를 준비하고 profile을 실행·비교하는 방법
- Cloud Data Quality 자산(Cleanse, Deduplicate, Labeler, Parse, Rule specification, Verifier)과 Dictionary의 쓰임
- Rule specification으로 exception record를 표시하고 exception task로 처리하는 흐름
- 온프레미스 IDQ에서 Analyst tool과 Developer tool을 나눠 쓰는 방법
- Rule Specification을 mapplet으로 생성해 Developer 쪽 mapping에 연결하는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Profile | data profiling task라고도 한다. 소스 객체 컬럼의 value frequency, pattern, data type, null·distinct 값을 뽑는다. filter, rule, schedule을 붙일 수 있다. |
| Secure Agent / Runtime environment | 작업을 실행하는 플랫폼. 조직마다 runtime environment가 최소 하나 있어야 task를 돌릴 수 있다. |
| Scorecard | Cloud profile에서는 rule occurrence와 함께 다룬다. 온프레미스 Analyst 튜토리얼 Lesson 6에서 직접 만들고 실행한다. |
| Rule Specification | 비즈니스 규칙의 데이터 요건을 논리 형태로 표현한 자산. input, rule set, rule statement로 구성된다. |
| Rule Statement | input, operator, condition, action으로 이뤄진다. condition은 분석 종류를, action은 조건 충족 시 출력을 정한다. |
| Dictionary | mapping에서 데이터를 대조하는 reference data set. 표준값을 담은 컬럼(valid column)이 최소 하나 있어야 한다. |
| Cleanse / Parse / Verifier | 값을 표준화하는 자산, 패턴 기반·사용자 정의로 값을 쪼개는 자산, 주소를 검증하는 자산. |
| Deduplicate | 중복 레코드를 찾는 자산. field type과 identity objective를 설정한다. |
| Exception task | rule specification이 exception indicator를 붙인 레코드, 즉 미해결 품질 문제가 남은 레코드를 처리한다. |
| Model Repository | Developer·Analyst tool의 프로젝트·폴더 메타데이터를 담는 관계형 DB. 편집 중인 asset은 잠긴다. |

## 실습 흐름 (LAB)
1. 호환 브라우저(Chrome 62 이상, Firefox 64-bit 56 이상, IE11은 CORS 활성화 필요)를 확인한다. [Getting Started (Data Profiling)]
2. Windows나 Linux에 Secure Agent를 설치하고 Secure Agent group으로 runtime environment를 만든다. [Getting Started (Data Profiling)]
3. Administrator의 Connections 페이지에서 소스 connection을 만든다. [Getting Started (Data Profiling)]
4. Explore page에서 project와 folder를 만들고 profile을 생성해 실행한다. 결과 탭에서 run 비교, 결과 export, value frequency의 dictionary export를 해 본다. [Getting Started (Data Profiling)], [Data Profiling]
5. 온프레미스 Analyst tool로 Lesson 1~8을 따라간다. data object 생성, default·custom profile, expression rule, scorecard, profile 컬럼 기반 reference table 생성까지 한다. [Data Quality Getting Started Guide], [Profiling Getting Started Guide]
6. Developer tool로 physical data object를 가져와 profile을 돌리고, parsing → standardizing → address validation 순서로 데이터를 정제한다. [Data Quality Getting Started Guide]

## 현업 팁 · 주의점
- 기본값으로 소스가 100,000,000행을 넘으면 컬럼마다 subtask를 하나씩 만든다. Minimum Number of Rows for Split Process per Column으로 조정하고, Administrator에서 Secure Agent 동시 실행 수도 함께 맞춘다.
- Explore page는 # ? ` | { } " ^ & [ ] / \ 문자를 지원하지 않는다. project, folder, asset, tag 이름에 쓰지 않는다.
- Profile 이름은 저장 폴더 안에서 고유해야 하고 특수문자를 쓸 수 없다. 위치를 지정하지 않으면 Default project에 저장된다.
- Rule specification은 mapplet을 만들기 전에 validate하고, 샘플 값으로 test해 출력이 규칙 요건에 맞는지 확인한다.
- Developer tool의 domain search는 결과가 2048개를 넘으면 표시되지 않는다. Analyst tool 검색은 Search Service가 켜져 있어야 한다.
