# P3. Application Integration & API
> Process와 Service Connector로 REST/SOAP 서비스를 엮어 실시간 연동을 만들고, 게시한 Process를 API Center에서 Managed API로 감싸 정책을 걸고 운영하는 단계다.

## 이 단계에서 배우는 것
- Process Designer(BPMN 기반)에서 Start/End 사이에 step을 끌어다 놓아 Process를 설계하고 게시·호출하는 흐름
- WSDL·Swagger·OpenAPI 3.0 파일을 가져와 Service Connector와 App Connection을 만드는 방법
- Parallel Paths, Subprocess, Fault Handling(Catch Faults)으로 분기·재사용·오류 처리를 넣는 방법
- Application Integration Console에서 프로세스 인스턴스, 스케줄, API 활성 상태, 리스너 이벤트 소스를 관리하는 방법
- API Center에서 Published API → Managed API를 만들고 Security·Rate limit·CORS·IP filtering 정책을 거는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Process | 비즈니스 프로세스를 자동화하는 asset. HTTPS 기반이면 게시 시 REST/SOAP API가 생기고, 이벤트 기반이면 이벤트 발생 시 실행된다. |
| Guide | 사용자가 자주 거치는 화면 흐름을 자동화하는 asset. 게시하면 embed code가 생성돼 서드파티 앱에 넣을 수 있다. |
| Service Connector | REST/SOAP API를 노출한 서비스와 통신하는 정의. 직접 만들거나 WSDL·Swagger·OpenAPI 파일을 import하거나 GitHub·Marketplace·Administrator에서 내려받는다. |
| App Connection | Service Connector나 native connector를 Process·Guide에서 쓰기 위한 연결. 별도로 게시해야 한다. |
| Process Object | 이름·주소·전화번호처럼 묶인 구조화 데이터를 정의한 객체. standalone으로 만들면 여러 Process에서 재사용한다. |
| Cloud Server / Secure Agent | Process를 배포·실행하는 런타임. Cloud Server, 특정 Secure Agent, Secure Agent group 중 하나에 배포해 호출한다. |
| Fault Handling | step의 Fault Handling 탭에서 Catch Faults를 켜면 fault/no fault 두 분기가 생긴다. HTTPS 500 대신 정의한 값을 돌려줄 수 있다. |
| Application Integration Console | 런타임 모니터링 화면. 인스턴스 상태(Running, Suspended, Completed, Compensatable, Faulted), 스케줄, APIs, Connections, Logs를 본다. |
| Managed API | 인증 방식과 사용 정책을 통일한 API. Published API를 골라 만들고 활성화하면 API Center가 endpoint URL을 생성한다. |
| API Policy | Security, CORS, Operational(Rate limit·Response caching), Privacy(PII), IP filtering 정책. API나 operation에 할당한다. |

## 실습 흐름 (LAB)
1. Product Availability Matrix로 브라우저 호환성을 확인하고 runtime environment(Secure Agent 1개 이상)를 준비한다. Explore 페이지에서 Project와 Folder를 만든다. [Getting Started]
2. New > Processes > Process로 Process를 만들고 Start step에서 속성과 Output을 설정한다. Save·Publish 후 호출하고 Application Integration Console에서 실행 결과를 확인한다. 두 번째 Process는 입력 텍스트를 받아 그대로 출력한다. [Tutorial Hello World]
3. Service Connector from WSDL로 calculator 웹서비스 커넥터를 만들고 Test Actions로 확인한 뒤 App Connection을 만든다. [Tutorial Calculator]
4. 두 정수를 입력받아 Add·Subtract·Multiply·Divide를 병렬로 실행하는 Process를 만든다. Properties Detail에서 Service URL을 복사해 10/5, 8/0으로 호출해 본다. [Tutorial Calculator]
5. Divide Service step에 Catch Faults를 켜고 Output을 고친다. 8/0 재호출 시 Sum 8, Difference 8, Product 0, Quotient Fault가 나오고, Console에서 process version이 하나 올라간 것을 확인한다. [Tutorial Calculator]
6. (선택) JDBC Connection을 만들고 Create step으로 결과를 calculatorArchive 테이블에 보관한다. [Tutorial Calculator]
7. Explore > Import로 Get Inventory Detail 커넥터·연결을 가져오고, Swagger로 Margin·Email Service Connector를 만든다. Temporary Field와 Assign으로 입력을 구성한다. [Tutorial Order Management]
8. Send Email Process를 Subprocess로 Parallel Paths 두 분기(소비자·공급자)에 넣는다. 없는 ItemName으로 fault를 재현한 뒤 Get Inventory Detail step에 Catch Faults를 건다. [Tutorial Order Management]
9. API Manager의 API Registry에서 Order_Management Process로 Create Managed API를 실행하고 managed API로 호출한다. [Tutorial Order Management]
10. Recipes 메뉴에서 recipe를 검색·복사하고 App Connection 인증과 runtime environment를 설정한 뒤 asset을 게시한다. [Getting Started With Recipes]

## 현업 팁 · 주의점
- Project, folder, asset, tag 이름에 `# ? ' | { } " ^ & [ ] / \` 문자를 쓸 수 없다. [Getting Started]
- bulk publish/unpublish는 한 번에 최대 199개 asset까지이고 INFA-SESSION-ID 헤더가 필요하다. 게시 후 수정한 Guide는 다시 게시하지 않으면 Outdated 상태로 남는다. [Invoke]
- APIs 페이지에서 비활성화한 API는 Process를 재게시해도 다시 켜지지 않는다. APIs 페이지에서 직접 activate해야 한다. [Monitor]
- Rate limit 기본값은 조직 단위 분당 1,000건, 최대 분당 10,000건이다. Response caching timeout은 최대 3,600초이고 upstream 응답이 압축돼 있으면 캐시가 동작하지 않는다. [API Policies]
- 같은 API에 IP filtering allow 규칙과 deny 규칙을 섞어 쓸 수 없다. 요청 IP와 처음 일치하는 규칙이 적용된다. [API Policies]
