# P1. Cloud Data Integration (CDI) 핵심
> Mapping, Transformation, Task, Taskflow를 조합해 배치 ETL/ELT 파이프라인을 직접 만들고 실행·모니터링한다.

## 이 단계에서 배우는 것
- Project, Folder, Asset 구조와 Explore 페이지에서 자산을 관리하는 방법
- Mapping Designer에서 Source → Transformation → Target 데이터 흐름을 설계하고 Parameter로 재사용하는 방법
- Mapping task, Synchronization task, Replication task 등 Task 유형별 쓰임새
- Taskflow와 Linear taskflow로 여러 Task의 실행 순서를 제어하는 방법
- My Jobs 페이지와 로그 파일로 Job을 모니터링하고 문제를 찾는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Mapping | Mapping task에서 재사용하는 데이터 흐름 로직. 서로 다른 시스템의 소스 조인처럼 Synchronization task로는 안 되는 로직을 정의한다. |
| Mapping in advanced mode | 다단계 계층형 데이터, 코드 스니펫, 대규모 워크로드를 처리하는 Mapping. 실행하려면 advanced cluster가 필요하다. |
| Transformation | Mapping 안에서 데이터에 적용하는 연산. 행 수를 바꾸면 active(예: Filter), 바꾸지 않으면 passive다. |
| Parameter | 실행 시점에 값을 정하는 자리표시자. Input parameter는 Task 설정 시 값을 넣고, In-out parameter는 실행마다 바뀌는 값(예: 증분 타임스탬프)을 담는다. |
| Mapping task | Mapping의 로직에 Task 파라미터와 parameter file 값을 더해 실행하는 Task. Mapping이 먼저 있어야 만들 수 있다. |
| Dynamic mapping task | 같은 Mapping으로 파라미터 값이 다른 여러 Job을 한 Task에 묶어 그룹·순서대로 실행한다. 파라미터가 하나 이상 있는 Mapping만 쓸 수 있다. |
| Synchronization task | 소스와 타겟 간 데이터를 동기화한다. Insert, Update 같은 Task operation을 고르고 Database, Flat file, Salesforce를 지원한다. |
| Taskflow | 이전 Task 결과에 따라 실행 순서를 제어하는 오케스트레이션 자산. 병렬 실행, 분기 판단, 대기 시간 설정이 가능하다. Linear taskflow는 지정한 순서대로 직렬 실행만 한다. |
| Mapplet | Mapping에 넣어 쓰는 재사용 Transformation 로직. PowerCenter mapplet을 가져올 수도 있고, 서로를 순환 참조할 수는 없다. |
| Job | Mapping, Task, Taskflow를 실행할 때마다 만들어지는 인스턴스. My Jobs 페이지에서 상태 확인, 중지·재시작, 로그 다운로드를 한다. |

## 실습 흐름 (LAB)
1. Product Availability Matrix로 지원 OS·DB·브라우저를 확인하고 지원 브라우저로 로그인한다. [CDI Quick Start]
2. Administrator > Runtime Environments에서 Secure Agent를 설치한다. SaaS 데이터에 접근할 때는 설치가 필요 없는 Hosted Agent를 쓸 수 있다. [CDI Quick Start] [Getting Started]
3. 필요하면 add-on connector를 설치하고 Connections 페이지에서 Connection을 만든 뒤 테스트한다. [CDI Quick Start]
4. (선택) Administrator > Settings에서 source control을 켜고 저장소를 연결한 뒤 Data Integration에서 객체를 check in 한다. [CDI Quick Start]
5. Explore 페이지에서 New Project, New Folder로 작업 공간을 만든다. 폴더는 한 단계까지만 만들 수 있다. [Getting Started]
6. Data Integration에서 New > Mapping > Create로 Mapping을 만들고 소스에서 타겟까지 흐름을 구성한 뒤 실행한다. [CDI Quick Start]
7. 연습 시나리오: 미국 고객 계정 파일을 Source로 두고, 주(state) 값을 Parameter로 받는 Filter transformation을 넣는다. 타겟 객체도 Parameter로 만든 뒤 Validate, Test하고 Mapping task로 만든다. [Mappings > Mapping tutorial]
8. My Jobs 페이지에서 Job 상태를 보고, 오류가 나면 로그 파일을 내려받아 원인을 찾는다. [CDI Quick Start]
9. 다음으로 Task, Taskflow, Component를 만들어 본다. [CDI Quick Start Next Steps]

## 현업 팁 · 주의점
- Filter transformation은 소스 가까이 두어 불필요한 행을 일찍 걸러야 성능이 좋아진다.
- SQL ELT mode Mapping에서는 Informatica 함수 대신 대상 클라우드 DW의 네이티브 함수와 문법을 쓴다. User-defined function도 쓸 수 없다.
- Connection parameter로 Mapping task에서 쓸 Connection을 고를 수는 있다. Connection 속성 자체는 파라미터로 만들 수 없다.
- CDC나 Kafka 같은 실시간 소스를 Dynamic mapping task에 넣으면 같은 그룹과 뒤 그룹의 Job이 늦어질 수 있다. 이런 경우는 Mapping task로 분리한다.
- Parameter set의 값은 `=` 뒤 모든 문자(앞뒤 공백 포함)를 문자열로 읽는다. 연결 비밀번호 같은 민감 정보는 별도 parameter file로 나눈다.
