# P6. PowerExchange & CDC (On-Prem)
> 메인프레임·레거시 DB를 Data Map으로 관계형처럼 읽고, 로그 기반 CDC로 변경분만 PowerCenter에 흘려보내는 단계다.

## 이 단계에서 배우는 것
- IBM i, Linux/UNIX, Windows, z/OS에 PowerExchange를 full·upgrade·hotfix 방식으로 설치하는 절차
- PowerExchange Navigator로 Data Map, Capture Registration, Extraction Map을 만들고 Database Row Test로 검증하는 방법
- PowerExchange Listener 기반 Bulk Data Movement로 타깃을 초기 적재(materialize)하는 방법
- LUW·z/OS 소스별 CDC 구성(Logger, Agent, Condense)과 변경 데이터 추출
- PWXPC와 PowerExchange for SAP NetWeaver로 PowerCenter 매핑·세션에 연결하는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| PowerExchange Listener | Data Map을 저장·관리하고 bulk 데이터를 PowerCenter와 Navigator에 제공한다. 소스가 원격 시스템(z/OS 등)에 있으면 그 시스템에 별도 Listener가 필요하다. |
| PowerExchange Navigator | Windows용 GUI. Data Map, 등록, 추출 맵 같은 PowerExchange 객체를 정의하고 관리한다. |
| Data Map | Adabas, IMS, IDMS, VSAM, SEQ 같은 비관계형 소스를 관계형 행 뷰로 보여 주는 정의. SQL 형태로 읽고 쓰려면 반드시 있어야 한다. |
| Copybook | 레코드·세그먼트·필드·키 정의를 통칭한다. COBOL, PL/I copybook이나 IMS DBD, Adabas FDT를 Data Map으로 가져온다. |
| Registration Group / Capture Registration | CDC 대상 데이터셋·테이블을 등록하는 객체. 등록이 없으면 변경 캡처가 안 된다. |
| Extraction Group / Extraction Map | 캡처된 변경 데이터를 추출하는 정의. Change Indicator, Before Image 컬럼을 추가하거나 뺄 수 있다. |
| PowerExchange Logger | LUW와 z/OS 각각에 있는 CDC 컴포넌트. z/OS 쪽은 PowerExchange Agent, PowerExchange Condense와 함께 구성한다. |
| Database Row Test | 리소스의 데이터를 미리 보고, Listener LISTTASK/STOPTASK 명령을 내리고, CDC용 restart token을 생성한다. |
| DBMOVER | Listener 동작을 정하는 구성 파일. TCP/IP 포트, 로그 파일, 튜닝 구문을 여기서 설정한다. |
| PWXPC | PowerExchange Client for PowerCenter. PowerCenter 매핑·connection·세션에서 PowerExchange 소스를 쓰게 하고 restart/recovery를 제공한다. |

## 실습 흐름 (LAB)
이 단계에는 lab 문서가 없다. 아래는 문서에 나온 기능만으로 구성한 권장 실습 순서다.
1. OS·소스·타깃 버전 요건과 License Key를 확인하고 Windows에 full installation을 수행한다. 64-bit 머신에서는 Navigator 설치 옵션을 고른다. [Installation And Upgrade Guide]
2. DBMOVER 파일을 수정하고 TCP/IP 포트를 지정한 뒤 PowerExchange Listener를 기동한다. [Bulk Data Movement Guide]
3. Navigator에서 PowerExchange가 제공하는 예제 Data Map·copybook·데이터 파일로 single-record Data Map을 만들고 COBOL copybook을 가져온다. [Navigator User Guide]
4. Database Row Test로 Data Map이 실제 데이터를 읽는지 확인한다. [Navigator User Guide]
5. Oracle이나 Db2 LUW 같은 관계형 소스는 Data Map 없이 PowerCenter Designer에서 메타데이터를 가져와 bulk 세션을 만든다. [Bulk Data Movement Guide]
6. CDC 소스에 Registration Group과 Capture Registration을 추가하고, Extraction Map을 확인한 뒤 Database Row Test로 restart token을 생성한다. [Navigator User Guide]
7. PWXPC connection을 만들고 CDC 세션을 구성해 Workflow Monitor에서 진행 상황을 본다. [PowerExchange Interfaces For PowerCenter], [Bulk Data Movement Guide]

## 현업 팁 · 주의점
- 업그레이드는 소스·타깃 시스템, Navigator용 Windows, PowerCenter Client(또는 Developer), Integration Service(또는 Data Integration Service) 시스템 모두에 해야 한다. PowerCenter 업그레이드와 일정을 맞춘다.
- Datacom과 IDMS는 bulk 읽기만 된다. 타깃으로 쓸 수 없다.
- 쓰기 모드를 고를 때 따져 볼 점이 있다. Synchronous는 무결성과 복구를 지키지만 느리다. Asynchronous는 빠르지만 복구가 안 된다. Asynchronous with Fault Tolerance는 오류를 reject file과 로그로 남긴다.
- 문서마다 PowerExchange와 PowerCenter 간 환경 변수 비호환 항목이 있다. 같은 머신에 둘을 함께 설치할 때 먼저 읽는다.
- Bulk로 타깃을 materialize한 뒤 CDC로 변경분만 반영하면 타깃 갱신이 빨라진다.
