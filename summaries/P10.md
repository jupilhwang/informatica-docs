# P10. Master Data Management (MDM)
> Business 360 Console에서 business application을 설정하고 Business Entity·Match and Merge·360 앱으로 마스터 레코드를 만든다. 온프렘 Multidomain MDM은 필요할 때 따로 본다.

## 이 단계에서 배우는 것
- Business 360 Console에서 business application을 먼저 설정하고 데이터 모델을 정의하는 순서
- Source record, trust score, survivorship으로 best version of the truth를 만드는 원리
- Match and Merge 설정: candidate selection, key generation level, candidate search level, ML 모델과 declarative rule
- Customer 360 / Product 360 / Supplier 360 / Multidomain MDM SaaS의 공통 화면(레코드, 대시보드, 리포트, 계층, 태스크)
- Reference 360의 reference data set, code list, crosswalk 구조와 온프렘 MDM Hub의 hierarchy 구성

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Business 360 Console | MDM 프로젝트를 만드는 곳. 라이선스가 있는 business application을 설정하면 predefined asset이 org에 로드된다. |
| Business Entity | 마스터 데이터 모델 단위. Customer 360은 Person/Organization, Product 360은 Item/Category, Supplier 360은 Supplier/Contact를 쓴다. |
| Source record / Master record | 소스 시스템별 데이터는 source record로 저장되고, 가장 믿을 만한 값을 모아 master record를 만든다. |
| Trust score / Survivorship | 필드 값의 신뢰도와 관리자가 정한 생존 규칙. 둘을 합쳐 best version of the truth를 정하고 필요하면 수동 override한다. |
| Match and Merge | 중복 레코드를 찾아 합치는 과정. ML model, declarative match rule, 또는 둘 다 쓴다. |
| Key generation level | 매치 키를 얼마나 촘촘히 만들지 정한다. Extended(소량·저품질), Standard(중간), Limited(대량·고품질) 중 고른다. |
| Candidate search level | 매치 후보 검색 강도. Exhaustive, Extreme, Narrow, Typical 중 고른다. 규칙은 전체가 아닌 후보에만 적용된다. |
| Ingress / Egress job | 외부 소스에서 Business 360 data store로 적재하는 작업과 반대로 내보내는 작업. |
| Reference data set / Code list / Crosswalk | 참조 데이터 범주, 애플리케이션별 코드 값 묶음, 코드 리스트 간 단방향 value mapping. |
| Entity base object / Hierarchy profile | 온프렘 MDM Hub에서 계층을 구성하는 객체. entity type과 relationship type을 hierarchy profile에 묶는다. |

## 실습 흐름 (LAB)
1. Business 360 Console에서 라이선스가 있는 business application을 먼저 설정한다. predefined asset이 로드된 것을 확인한다. [Getting Started]
2. 데이터 모델을 설계하기 전에 Limits and thresholds와 Identifiers 절을 읽는다. 이어서 MDM SaaS 버전과 라이선스 만료 정보를 확인한다. [Getting Started]
3. Reference 360 준비: Administrator에서 SAML 설정 또는 사용자 생성, Reference 360 역할 부여, 그룹 생성 후 사용자를 배정한다. REST API로 metadata picklist 값을 추가한다. [Reference 360 Quickstart]
4. Country Codes reference data set을 만들고 그 안에 CRM Country Codes와 Marketing Country Codes code list를 만든다. [Reference 360 Quickstart]
5. 각 code list에 code value를 만들거나 가져온다(예: "United States of America"와 "UNITED STATES OF AMERICA"). [Reference 360 Quickstart]
6. CRM에서 Marketing 방향으로 crosswalk를 만들고 두 값을 value mapping으로 연결한다. 이후 hierarchy를 만들고, 변경을 제안하고, draft 승인 요청까지 이어 간다. [Reference 360 Quickstart]
7. (온프렘 선택) Hub Console Hierarchies 도구로 Product hierarchy를 구성한다. Product base object를 entity base object로 바꾸고, entity type 2개와 relationship type 2개를 만든다. hierarchy profile, package 생성·할당, Hierarchy Manager 표시 설정 순으로 진행한다. [Mdm hierarchy configuration tutorial]

## 현업 팁 · 주의점
- 매치 설정 전에 실제 운영 데이터 샘플로 완전성과 품질을 감사한다. 문서 예시대로 postal code가 50% 레코드에만 있으면 exact match 필드로 부적합하다.
- 빈도가 높은 전화번호, 이메일, 단어는 동일 키를 대량으로 만든다. 후보 목록이 커지므로 정제하거나 억제하고, 대용량이면 state/country code로 후보를 필터링한다.
- ingress/egress job은 매시간 스케줄하지 않는다. 이전 작업이나 대용량 데이터 때문에 실패한다. 병렬 실행과 성능을 위해 Business 360 connector 대신 Business 360 FEP connector를 쓴다.
- predefined asset은 지우지 않는다. 커스텀 asset은 X_<asset name>으로 이름을 붙이고, Business360·Customer360 같은 predefined project 대신 별도 project에 만든다.
- source primary key에 /, \, ., %, ;, "는 넣지 않는다. 255자를 넘으면 잘린다. draft 기능과 task inbox는 preview라서 운영 환경에서는 지원되지 않는다.
