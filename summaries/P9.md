# P9. Data Governance & Catalog
> Metadata Command Center로 메타데이터를 추출하고, Data Governance and Catalog에서 기술·비즈니스 자산을 연결·보호한 뒤, Data Marketplace로 데이터를 셀프서비스 공급하는 거버넌스 체계를 세운다.

## 이 단계에서 배우는 것
- Metadata Command Center(MCC)에서 소스 시스템 메타데이터를 추출·프로파일링·분류하는 흐름
- Data Governance and Catalog(CDGC)의 기술 자산과 비즈니스 자산(Glossary, Policy, Process 등)의 차이와 연결 방법
- 검색, Relationships, Data lineage, 감사 이력으로 자산을 찾고 추적하는 방법
- Metadata access control과 Data Access Management로 메타데이터와 실제 데이터 접근을 따로 통제하는 방법
- Data Marketplace에서 data collection을 게시하고 주문·승인으로 데이터를 전달하는 구조

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Metadata Command Center | DB, 데이터 레이크, 웨어하우스 등에서 메타데이터를 추출·저장·보강하는 서비스. 프로파일링, 분류, 관계 탐색, 접근 정책 관리도 여기서 한다. |
| Catalog Source | 메타데이터 추출 설정 단위. 추출 설정, 활성화한 capability, 프로파일링 필터, 작업 스케줄에 따라 CDGC에 보이는 기술 자산이 달라진다. |
| Technical asset | 소스에서 추출한 데이터 표현. Data element(컬럼·필드), Technical data set(테이블), Data container로 나뉜다. |
| Business asset | 데이터를 왜, 어디서, 어떻게 쓰는지 설명하는 자산. Glossary Business Term, Metric, Policy, Process, AI Model, Regulation 등이 있다. |
| Glossary Domain / Business Term | 비즈니스 용어집 계층. 용어를 기술 자산에 연결(Glossary association)해 비즈니스 맥락을 붙인다. |
| Data lineage | 원천 시스템부터 목적지까지 데이터 흐름을 시각화한 것. 상류 출처와 하류 영향 범위를 파악한다. |
| Access policy / Asset group | MCC에서 정의하는 메타데이터 접근 규칙. 역할·자산 그룹·attribute group 단위로 볼 수 있는 자산과 속성을 제한한다. |
| Data access policy | Data Access Management의 실제 데이터 보호 정책. Data access control, Data filter, Data de-identification 세 가지가 있다. |
| Precedence tier | Data de-identification 정책의 평가 순서를 정하는 그룹. 티어 안에서는 위에서 아래로, 티어끼리는 낮은 숫자부터 평가한다. |
| Data collection | Data Marketplace에서 Data Owner가 데이터 자산을 묶어 게시하는 단위. Data User가 검색해 주문한다. |

## 실습 흐름 (LAB)
1. IDMC My Services에서 Metadata Command Center 타일을 열어 로그인한다. 관리자가 서비스 접근 권한을 먼저 부여해야 한다. [Metadata Command Center Introduction And Getting Started]
2. MCC Home 대시보드와 Explore를 둘러보고, Import predefined content로 기본 콘텐츠를 가져온다. 사내 보안 정책상 필요하면 Secure Agent에서 메타데이터 작업을 실행한다. [Metadata Command Center Introduction And Getting Started]
3. Manage access to assets 장을 따라 Predefined user roles와 Predefined access policies를 확인하고, 실습 계정에 필요한 Asset privileges와 Feature privileges를 점검한다. [Metadata Command Center Introduction And Getting Started]
4. Data Governance and Catalog에 로그인해 Home page에서 추출된 자산을 확인하고, Import assets로 비즈니스 자산을 가져온다. [Data Governance and Catalog Introduction And Getting Started]
5. 가져온 자산을 검색·탐색하고 lineage와 관계를 열어 본다. Bulk import 결과는 Job Monitoring에서 상태와 로그를 확인한다. [Data Governance and Catalog Introduction And Getting Started]
6. Data Marketplace에 접속해 Predefined roles를 배정한 뒤 흐름을 한 번 돌린다. Administrator가 data asset과 delivery template을 준비하고, Data Owner가 data collection을 게시하고, Data User가 주문하고, Data Owner가 승인한다. [Data Marketplace Introduction And Getting Started]
7. Guide Me 패널과 My Data 페이지에서 주문 상태와 받은 데이터를 확인한다. [Data Marketplace Introduction And Getting Started]

## 현업 팁 · 주의점
- CDGC에서 보이는 기술 자산은 MCC의 catalog source 설정(추출 설정, capability, 프로파일링 필터, 스케줄)에 달려 있다. 자산이 안 보이면 MCC 설정부터 확인한다.
- 검색 결과도 access policy로 걸러진다. 자산이 없는 것인지 권한이 없는 것인지 먼저 구분한다.
- Metadata access control은 최소 권한 원칙을 따른다. 처음에는 access policy를 몇 개만 만들어 디버깅을 쉽게 하라고 문서가 권한다.
- 게시된 data access 자산을 수정하면 draft 사본이 생긴다. draft를 게시할 때까지는 기존 게시본이 계속 적용된다. 검토가 필요하면 workflow를 켠다.
- Tokenize 표현식은 anchor, backreference, capture group, 무한 반복, \d·\w 같은 축약 문자 클래스를 지원하지 않는다. 자산 감사 이력은 2년간 보관된다.
