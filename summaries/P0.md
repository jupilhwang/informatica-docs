# P0. 오리엔테이션 & IDMC 플랫폼 기초
> IDMC의 조직·사용자·런타임 구조를 이해하고, Secure Agent와 Connection을 갖춘 실습 환경을 직접 만든다.

## 이 단계에서 배우는 것
- Organization, Sub-organization, License, Metering(IPU)으로 이루어진 IDMC 조직 구조
- User, User group, Role, Permission으로 접근 권한을 나누는 방법
- Runtime Environment의 종류(Hosted Agent, Secure Agent group, Elastic, Serverless)와 선택 기준
- Windows/Linux에 Secure Agent를 설치·등록하고 서비스 구성을 확인하는 절차
- Administrator의 Connections 페이지에서 Connection을 만들고 테스트하는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Organization | 라이선스, 사용자 계정, Mapping·Task 같은 자산, 작업·보안 정보를 담는 IDMC 저장소 안의 보안 영역. 무료 체험으로 만든 조직은 기본적으로 production organization이다. |
| Sub-organization | production organization의 하위 조직. 자산·Connection·Runtime Environment·사용자를 따로 가지며, 상위 조직이 Runtime Environment와 add-on connector를 공유할 수 있다. |
| IPU (Informatica processing unit) | usage-based 라이선스의 사용량 단위. 작업을 실행하면 소비되고, Metering 페이지에서 구매·소비·잔여량을 본다. |
| Runtime Environment | Task와 Taskflow를 실행하는 플랫폼. 조직마다 최소 하나가 있어야 사용자가 Task를 실행할 수 있다. |
| Secure Agent | Task를 실행하고 방화벽 너머 IDMC와 사내 시스템 간 보안 통신을 맡는 경량 프로그램. 연결이 끊기면 재연결을 시도하고, 실패하면 Task가 실패한다. |
| Hosted Agent | Informatica 클라우드 시설에서 돌아가는 런타임. 설치할 것이 없지만 지원 Connector가 정해져 있고 추가·설정이 불가능하다. |
| Serverless runtime environment | Secure Agent 설치·유지 없이 쓰는 단일 테넌트 런타임. 워크로드에 맞춰 자동 확장되고 데이터는 고객 클라우드에 남는다. |
| Secure Agent services | Agent가 쓰는 플러그형 마이크로서비스. Data Integration Server는 Mapping·Task·Taskflow를, Process Server는 Application Integration 프로세스를 실행한다. |
| Role / Permission | Role은 자산·기능별 privilege 묶음이다. Permission은 Secure Agent, Connection, Schedule, 자산 단위로 read/update/delete/execute 권한을 추가로 건다. |
| Connection | 소스·룩업·타겟 위치를 지정하는 접속 정보. Connector로 만들며, 실행 중인 Agent가 있는 Runtime Environment를 지정해야 한다. |

## 실습 흐름 (LAB)
1. 호환 브라우저와 Product Availability Matrix를 확인하고 Runtime Environment가 있는지 점검한다. [Getting Started (Data Quality)]
2. Agent 설치 전제조건을 확인한다. 지원 OS, 여유 디스크 5 GB 이상, 플랫 파일 디렉터리 접근 권한, 방화벽에서 IDMC 도메인과 443(HTTPS) 허용. [Secure Agent Quick Start for Linux/Windows]
3. Administrator > Runtime Environments에서 Download Secure Agent를 누르고 OS 플랫폼을 고른 뒤 install token을 복사한다. [Secure Agent Quick Start for Linux/Windows]
4. Linux는 `./agent64_install_ng_ext.bin -i console`로 설치하고 `apps/agentcore`에서 `./infaagent.sh startup`으로 시작한다. 이어서 `./consoleAgentManager.sh configureToken <user name> <install token>`으로 등록하고 `isConfigured`로 확인한다. [Secure Agent Quick Start for Linux]
5. Windows는 `agent64_install_ng_ext.exe`를 실행하고 Secure Agent Manager에서 User Name과 Install Token으로 Register한다. 이후 Services에서 Log On 계정을 지정하고 서비스를 재시작한다. [Secure Agent Quick Start for Windows]
6. 프록시를 쓰면 Linux는 `configureProxy`, Windows는 Secure Agent Manager의 Proxy 메뉴로 설정한 뒤 Agent를 재시작한다. [Secure Agent Quick Start for Linux/Windows]
7. Runtime Environments 페이지에서 상태가 "Up and Running"인지 확인한다. "Not all the services are running"이면 5–10분 기다린다. [Getting started with IICS]
8. Administrator > Connections > New Connection에서 Flat File Connection을 만든다. Runtime Environment, Directory, Date Format, Code Page를 지정하고 Test Connection 후 저장한다. [Getting started with IICS]
9. Data Integration > New > Mappings > Mapping을 만들고 Source에 Flat File Connection과 CSV 객체를 지정한 뒤 Preview Data로 확인한다. Target은 GCS·BigQuery Connection으로 잡는다. [Getting started with IICS]
10. Explore 페이지에서 New Project, New Folder로 자산을 정리할 프로젝트를 만든다. [Getting Started (Data Quality)]

## 현업 팁 · 주의점
- Secure Agent는 Task 실행과 운영 메타데이터 업로드를 위해 항상 떠 있어야 한다. 운영 서버처럼 상시 가동되는 머신에 설치한다.
- 설치 경로에 공백이 있으면 Linux 설치가 실패할 수 있다. PowerCenter가 있는 머신에서는 다른 OS 계정으로 설치해야 환경 변수 충돌을 피한다.
- Connection을 여러 Sub-organization에서 쓰려면 각 Sub-organization에 따로 만들어야 한다. add-on connector는 상위 조직에만 설치할 수 있다.
- Sub-organization으로 전환한 상태에서는 Taskflow 생성·게시·실행, data transfer task, dynamic mapping task 생성을 할 수 없다.
- 개발팀에는 Connection에 Read만 준 Developer role을 만들고, production Connection에는 개발 그룹 read 권한을 빼서 운영 데이터 사용을 막는다(User configuration examples).
