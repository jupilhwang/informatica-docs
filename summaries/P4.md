# P4. CDI 심화 & 운영
> 병목을 찾아 매핑과 Secure Agent를 튜닝하고, Advanced Cluster에서 advanced mode 매핑을 돌리며, REST API·RunAJob으로 작업을 자동화하고 Data Validation으로 결과를 검증하는 단계다.

## 이 단계에서 배우는 것
- thread statistics와 Filter transformation으로 source·target·mapping·system 병목을 찾아 하나씩 제거하는 튜닝 절차
- Secure Agent의 maxDTMProcesses, JVM 옵션, Linux ulimit, Amazon S3 파라미터 조정 기준
- fully-managed·self-service·local Advanced Cluster 구성과 advanced mode 매핑 실행·모니터링
- Platform REST API v2/v3, Data Integration REST API, RunAJob·ParamSetCli 유틸리티로 작업 자동화
- Monitor·Operational Insights로 작업을 감시하고 Data Validation·CLAIRE Copilot을 운영에 붙이는 방법

## 핵심 개념
| 개념 | 설명 |
|---|---|
| Bottleneck | 성능 저하 지점. target, source, transformation, system 중 어디인지 session log의 thread statistics(reader/transformation/writer 시간)로 판단한다. |
| Buffer memory | task 실행 시 source·target partition마다 최소 2블록씩 할당하는 메모리. 블록이 부족하면 task가 실패한다. 직접 지정하거나 run time 계산으로 둔다. |
| maxDTMProcesses | Data Integration Server의 custom property. 기본은 mapping task 2개만 동시에 돌고 나머지는 대기한다. 값을 올려 동시 실행 수를 늘린다. |
| Advanced cluster | 클라우드에서 분산 처리를 제공하는 Kubernetes 클러스터. fully-managed, self-service, local 세 유형이 있다. |
| Advanced configuration | 클러스터와 클라우드 리소스를 정의하는 속성 묶음. Administrator의 Advanced Clusters 페이지에서 만들고 runtime environment와 연결한다. |
| Mapping in advanced mode | Mapping Designer에서 Switch to Advanced로 전환한 매핑. transformation마다 runtime plan이 정해져 advanced cluster나 Data Integration Server에서 실행된다. |
| REST API v2 / v3 | v2는 serverUrl + /api/v2, 헤더 icSessionId를 쓴다. v3는 baseApiUrl + /public/core/v3, 헤더 INFA-SESSION-ID를 쓰고 JSON만 받는다. |
| RunAJob utility | REST API를 직접 부르지 않고 mapping task, taskflow 등을 실행·상태 확인하는 CLI. RunAJobCli 패키지 라이선스가 있어야 한다. |
| Operational Insights | IDMC 서비스(Data Integration, Application Integration 등)와 on-prem PowerCenter·DEI·DQ 도메인을 함께 모니터링하는 서비스 |
| Data Validation test case | 두 데이터셋(source·target)을 비교하는 테스트. 리포트에서 unmatched, missing, extra 데이터를 확인한다. |

## 실습 흐름 (LAB)
1. 클라우드 VM에 Secure Agent를 설치하고 클러스터 유형과 플랫폼(AWS, Google Cloud, Microsoft Azure, self-service, local)에 맞게 환경을 준비한다. [Integration At Scale Quick Start]
2. Administrator > Advanced Clusters에서 advanced configuration을 만들고 클러스터를 정의할 클라우드 리소스를 설정한다. [Integration At Scale Quick Start]
3. Data Integration에서 New > Mapping을 만들고 Mapping Designer에서 Switch to Advanced를 눌러 source → target 흐름을 정의한다. [Integration At Scale Quick Start]
4. Actions > New Mapping Task로 task를 만들고 advanced configuration이 연결된 runtime environment를 선택해 Run한다. [Integration At Scale Quick Start]
5. My Jobs에서 job을 열고 advanced cluster에서 돈 subtask로 내려가 결과와 Spark task details를 확인한다. [Integration At Scale Quick Start]
6. Monitor > Advanced Clusters에서 클러스터를 골라 activity log(기동·auto-scaling 이벤트)와 lifecycle graph(worker node 수 변화)를 본다. 여기서 보는 advanced configuration은 read-only다. [Integration At Scale Quick Start]
7. Templates 페이지에서 Data Vault – Hub tile로 mapping task를 만든다. landing table과 hub table을 source로, hub table을 target(Insert)으로 지정한다. [Data vault mapping task template configuration tutorial]
8. Input parameters에서 Hub Key `TO_CHAR(TRUNC(CUSTOMER_ID))`, Filter Existing Records `IIF(ISNULL(BK_CUSTOMER_ID),TRUE, FALSE)`를 입력한다. [Data vault mapping task template configuration tutorial]
9. Data Vault – Link 템플릿으로 주문·고객 hash key를 MD5로 계산하고 Link Key를 `MD5(Concat(...))`로 만든다. 기존 관계는 다시 insert하지 않는다. [Data vault mapping task template configuration tutorial]
10. Data Vault – Satellite 템플릿에서 Insert·Update 두 target을 설정하고 Change Compare 식으로 I/U/X를 판정해 변경 이력을 적재한다. [Data vault mapping task template configuration tutorial]

## 현업 팁 · 주의점
- maxDTMProcesses는 라이선스 범위를 넘기면 안 된다. 예: Secure Agent 3대 × 에이전트당 CPU 4개 라이선스면 12를 넘기지 않는다. [Secure agent best practices and tuning guidelines]
- DTM JVM의 -Xmx 기본값 64MB는 대용량·다중 partition 매핑에서 Java Heap Space 부족을 낸다. 권장값은 2024MB다. S3 Download Part Size(5MB)·Multipart Download Threshold(10MB)가 작으면 "Unable to download the files from S3" 오류가 나므로 512MB 정도로 올린다. [Secure agent best practices and tuning guidelines]
- Postman처럼 HTTP 버전을 자동으로 붙이는 도구에서는 URL에 HTTP 버전을 또 쓰지 않는다. 두 번 들어가면 요청이 실패한다. [REST API Reference]
- 클러스터 상태가 Unknown이면 먼저 Secure Agent가 실행 중인지 확인한다. 그래도 안 되면 관리자가 list-clusters로 상태를 보고 partial·in-use면 delete-clusters를 실행한다. [Advanced Clusters]
- Data Validation은 sub-organization에서 쓸 수 없고, 브라우저는 Chrome·Edge를 지원하며 성능 때문에 Chrome을 권장한다. Running Jobs 페이지는 완료 후 5분까지만 job을 보여 준다. [Introducing Data Validation] [Monitor]
